# 动作风险排序接口 v2：冻结协议

冻结日期：2026-10-22。协议标识：`action-risk-ranking-v2`。

## 研究问题

在不提供奖励、失能率、未来轨迹或最优动作的前提下，DeepSeek 能否把同一份当前观测与短期预测转化为对 9 个可执行动作有方向敏感性的风险排序？只有接口功能验收通过，才允许把该表示接入 MAPPO。

本协议不以 DeepSeek 获胜为目标。人工规则、透明数值评分器和 DeepSeek 使用完全相同的可观测状态；后续系统实验必须保留三者和纯 MAPPO。

## 公共接口

动作集合固定为：

- `wait`
- `north_025`、`north_050`、`north_075`、`north_100`
- `south_025`、`south_050`、`south_075`、`south_100`

模型必须返回一个 JSON 对象，只有 `actions` 和 `reason_codes` 两个顶层字段。`actions` 必须恰含上述 9 个动作，每个对象只有：

- `action_id`：固定动作标识；
- `risk_score`：0 到 1 的连续值，越低越好；
- `rank`：1 到 9 的唯一整数，1 为首选。

`reason_codes` 为 1–3 个固定枚举。接口不再接收自报置信度，不再用理由文本、触发器或远期阶段变化作为成功标准。解析器要求排名与风险分数顺序一致；物理安全检查独立拒绝把已封闭出口动作排在首位。

## 同信息三种转化器

1. **人工规则排序器**：使用封闭、出口烟气、出口容量、交汇占用及趋势作词典序排序。
2. **透明数值评分器**：使用同一字段计算连续风险，再排序；其公式和权重在 API 调用前冻结。
3. **DeepSeek 排序器**：接收同一 JSON 状态和动作定义，温度 0、关闭思考，只输出冻结结构。

三者都不得读取终点结果。通过功能验收只说明表示值得进入训练，不说明疏散收益。

## 冻结因素设计

使用两个训练侧物理区组，每个区组运行完整 `2^4` 因素设计，共 32 个状态，并以种子 `20261023` 随机化请求顺序。

| 因素 | 低水平 | 高水平 |
|---|---|---|
| 交汇拥堵 | 占初始人数 0.20 | 占初始人数 0.45 |
| 拥堵趋势 | 每步 −0.05 | 每步 +0.05 |
| 危险出口 | 北侧 | 南侧 |
| 临时封闭 | 无 | 北侧容量为 0 |

短期预测持续时间固定为 4 步，避免在一次准入中再次用远期阶段字段制造表面变化。每个区组保持总人数守恒。提示不含奖励、失能率、最优动作或未来模拟结局。

## 预先规定的准入标准

全部条件同时满足才可进入 MAPPO 训练：

1. 合法响应率至少 95%，关闭北出口时首选不得为北侧动作。
2. 每个响应包含 9 个唯一动作、1–9 唯一排名，排名与风险分数顺序一致。
3. **封闭敏感性**：北出口封闭时，北侧四动作平均风险至少增加 0.30。
4. **烟气方向敏感性**：在未封闭配对中，把危险出口从北改为南后，首选路线随安全侧翻转的比例至少 75%。
5. **严重度敏感性**：高拥堵相对低拥堵，使高放行动作（0.75/1.00）相对低放行动作（0.25/0.50）的平均风险差至少增加 0.08。
6. **趋势敏感性**：上升趋势相对下降趋势，使上述高低放行相对风险差至少增加 0.05。
7. DeepSeek 不能 32 次都给出相同完整排名；至少出现 4 种排名签名。

阈值在响应产生前冻结。不得因结果接近阈值而降低标准，也不得追加提示直到通过。

## 预算与停止规则

- 最多 32 次新请求；不自动重试。
- DeepSeek Flash，温度 0，关闭思考，JSON 输出，单次最多 512 输出 token。
- 保守费用硬上限 0.35 元；每次请求前写入预留，超时保留预留。
- 凭据仅通过当前 Windows 用户 DPAPI 在内存解密，禁止写入请求、缓存、报告或错误信息。
- 任一准入条件失败：记录负结果，MAPPO 新增训练步数保持 0，最终 48 个场景继续封存。

## 后续系统实验的边界

若通过，另行冻结训练协议；至少比较纯 MAPPO、规则风险排序 MAPPO、数值风险排序 MAPPO和 DeepSeek 风险排序 MAPPO。相同动作、物理约束、训练场景、训练种子数与环境步数。最终测试集只允许在该系统协议全部冻结且开发结果不再用于修改方案后读取一次。
