# 疏散过程证据审计：结果产生前固定方案

## 目的

本轮只修正指标解释并补齐过程记录，不训练、不调用DeepSeek API、不读取48个最终封存场景。原900回合实验、代码和报告保持原样，本轮输出作为独立补充证据。

原报告中的 `evacuation_time_seconds` 实际由回合控制步数乘5秒得到。环境在所有人员已经成功疏散或失能、活跃人数为零时结束。因此本轮将其明确命名为“回合结束时间”，不再单独解释为疏散效率。

## 固定输入和矩阵

- 重放事件触发器v3实验的相同十二个开发验证场景、五个保存训练种子和人口种子。
- 正常条件使用人口种子42001、42002；人工瓶颈条件仅使用45001。
- RAW34为共享参照；规则计划与DeepSeek新库分别重放legacy和v3，合计900回合。
- 使用保存权重确定性推理。DeepSeek臂只使用已有48条缓存，不产生付费请求。
- 人工瓶颈仍只将每侧交汇通行容量从12改为3，属于训练外压力诊断。

## 新增过程指标

每个控制步记录成功疏散、失能、滞留、请求联合动作、实际联合动作、请求放行比例、实际放行能力和实际放行人数。回合级指标包括：

- 回合结束时间；
- 最终成功疏散率、失能率、滞留率；
- 达到50%、80%、90%成功疏散的时间，未达到时保留为空；
- 成功疏散进度曲线的时间平均面积；
- 回合结束原因。

对有计划的控制步，记录当前阶段、计划方向、计划放行比例、计划联合动作，并比较MAPPO请求是否一致。该一致率只表示采用行为，不表示计划正确。

每次DeepSeek缓存检索记录查询事件、匹配案例、匹配案例事件、平方距离、候选数量、是否同事件匹配及完整计划。不存在同事件案例时，明确标记跨事件回退。

## 核验和停止条件

- 900回合身份网格必须完整，逐回合总人口恒等式必须成立，三类人数变化必须单调。
- 原有四个终点指标必须与冻结900回合CSV逐回合一致，最大绝对误差不超过1e-12。
- 每回合请求数不超过3，所有缓存请求均有可追溯计划；RAW不得出现计划。
- 完成固定900回合后停止，不依结果追加样本或调整瓶颈强度。

本轮不会检验新增拥堵计划是否有效。是否调用DeepSeek补齐拥堵案例，将根据过程审计确认的状态覆盖、匹配距离和采用链条另行冻结。
