# 事件触发v3：功能修复与有限开发诊断

## 范围与证据地位

六小时批次已完成，本文件属于随后独立协议。旧包装器、训练权重、计划库、原结果均不改写。
已有证据：原696回合中交汇区最高44人，未达到45人阈值；旧elif分支在构造越阈输入中漏报。
因此原条件的零差异是可以预期的回归检查，不能当作新的LLM有效性证据。

## 唯一代码修复

新增EventCorrectedPlanWrapper：先判断是否真的发生烟气反转，再按封闭变化、烟气反转、拥堵越线的优先级选择单一事件。保持每回合最多3次请求，初始请求计入；保持越阈去重和回落后再次越阈的行为。继承当前阶段烟气矛盾判断。

先用旧实现运行新测试：3失败、4通过。随后仅替换为v3：7项行为测试通过；与原包装器及扩展测试合计25项通过。

## 结果产生前固定的诊断矩阵

- 使用原24个生成开发场景的后12个，绝不读取48个最终封存场景。
- 使用20261301—20261305五个既有种子、弱监督e003_i002的规则与新DeepSeek库权重；另用共享RAW34权重作描述性基线。
- 正常条件：原EnvConfig，人口种子42001、42002。
- 瓶颈压力条件：仅将junction_to_branch_capacity从每侧12改为每侧3，其余条件保持；人口种子45001。它是额外的人工动力学压力诊断，不是真实建筑或独立最终测试，也不是根据LLM优劣挑选的条件。
- 规则和DeepSeek分别用同一个保存权重配对比较legacy与v3。RAW只运行一次，作为共享基线，不重复计独立样本。
- 共900回合：正常600、压力300；无训练、无新API调用。
- 记录每步观测、请求与实际联合动作、实际放行容量；每次重规划记录触发类型、时间与计划库是否存在同事件案例。
- DeepSeek臂使用既有48计划的近邻检索；它不等于实时DS推理。库没有拥堵事件案例时必须明确记录跨事件检索，不假定新增触发一定改善结果。

## 评价和停止

主要看同权重v3减legacy的失能率差；同时报告疏散时间、暴露、拥堵、触发次数和动作变化。五训练种子×十二场景交叉重采样仅作为开发诊断区间，不选择性报告。
正常条件要求旧分支终点与原CSV一致；核对每个协议的身份网格、请求上限、源文件和权重散列。压力条件即使有改善，也只能说明该人工条件下修复的影响。
全部固定900回合执行完即停止，不根据显著性补样或扩训。输出独立中文报告和原始CSV，随后再决定是否值得规划真正在线方案。
