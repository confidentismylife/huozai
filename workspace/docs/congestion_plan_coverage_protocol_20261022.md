# 拥堵计划覆盖：采集与有限验证冻结方案

## 研究问题

事件触发v3已经能够识别拥堵越阈，但现有48条DeepSeek缓存没有拥堵事件案例，86次历史拥堵请求全部跨事件回退。本轮检验：补齐少量同事件计划后，固定MAPPO权重能否更合理地使用计划，以及正确匹配的拥堵计划是否优于旧库、规则和置换计划。

这不是最终评估，也不以“让LLM获胜”为目标。最终48个场景继续封存。

## 状态采集

- 只使用24个生成开发场景中的前12个训练场景，不读取后12个验证结果来选择提示，也不读取最终场景。
- 使用弱监督设置 `e003_i002` 的规则臂、训练种子20261301和事件触发v3。
- 为产生已经明确标注为人工压力条件的拥堵状态，只将每侧交汇通行容量从12改为3。
- 依次使用人口种子45001、45002、45003；每个训练场景最多保留第一次拥堵越阈状态。
- 选择规则只依赖场景编号、事件类型和触发时间，不使用后续失能、时间或收益标签。
- 最多冻结12个状态。每个状态加入控制周期、观测单位、训练侧来源和人工瓶颈说明。

## DeepSeek调用预算

- 模型和提示沿用既有 `BudgetedPlanner`，温度0、JSON模式、关闭思考输出。
- 最多12个新请求，费用硬上限0.50元，无自动重试。
- 使用当前Windows用户DPAPI保存的凭据；密钥不得写入参数、日志或报告。
- 每个状态仅请求一次。模式不合法或传输失败保留失败记录和规则回退，不补抽新状态。
- 保存精确输入、响应、token、延迟、来源和保守费用；缓存命中不重复收费。
- 准入要求：合法计划比例至少95%，并单独审计第一阶段是否指向当前封闭出口、容量和等待语义。准入失败则停止，不进入终点对照。

## 固定权重有限对照

若准入通过，使用同五个弱监督DeepSeek权重和相同v3触发协议，在既有十二个开发验证场景的人工瓶颈条件、人口种子45001上比较：

1. 原48条缓存库；
2. 加入拥堵计划的扩充库；
3. 扩充库中拥堵计划按冻结置换表重新分配；
4. 同一DeepSeek权重接规则计划。

另报告独立训练规则权重和共享RAW34权重，作为系统级描述性参照；它们不与四种固定权重替换混为一个因果比较。五训练种子×十二场景是主要配对单位，人口重复不作为独立训练证据。

## 指标和停止规则

- 主要指标：最终失能率；同时报告成功疏散率、回合结束时间、成功疏散进度AUC、FED和拥堵。
- 机制指标：方向采用率、容量采用率、实际放行人数、请求次数、同事件匹配率和匹配距离。
- 重点比较扩充库减原库，以及正确匹配减置换。全部场景和不利结果都保留。
- 完成冻结矩阵即停止，不按显著性追加场景、种子、压力强度或API请求。
- 即使固定权重下出现改善，也只说明推理时覆盖有帮助；重新训练后的效果必须另行检验。
