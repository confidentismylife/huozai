## 1. 本轮真正解决了什么

我们补齐了“建议改变动作后，执行器实际做了什么，人员后来在哪里等待、吸入多少烟气”的证据。结论是：至少有两种不同的失败机制。第一种是方向建议与放行容量意外联动；第二种是同一方向建议在后续时刻再次被接受，其净收益已经改变。

保留无建议PPO的放行档位，能修复第一种问题中的特定病例，但仍不足以证明LLM加PPO稳定优于无建议PPO。这不是扩大训练的依据。

本轮完成：

- 1,920个完整回合：1,280个旧人口机制对照、640个新冻结人口回合；包括三个既有PPO控制版本及同信息规则。
- 94,742个实际控制步，记录请求动作、实际方向、实际放行上限及人数、区域FED与区域人数时间。
- 44个真实发生建议改动的状态，990条完整终点反事实；Rule用实际未来，概率行为用实际未来与三套冻结未来。
- 400个旧回合精确重现；44个原建议续跑的2,106个后续控制步精确重现。
- 独立脚本重新计算全部24组完整配对效果、44组状态分解及保持时间差中差；67个冻结文件哈希核对通过。
- 12项相关测试通过；实际动作不一致、封闭或超阈值走廊进入、放行超限、非法方向均为0。合规动作仍然可能增加暴露或失能，不能用违规数代替效果评价。

术语澄清：AULL0010、0013、0019、0020、0024是五个选过的开发情景，都使用同一个房间A、房间B、路口、北走廊、南走廊的五区域图结构，改变烟气参数、出口容量及阻塞条件。原完整报告里的“五个建筑”应理解为这五个参数化情景，不能理解成五座独立建筑。新人口、不同权重、未来随机种子也不是独立建筑样本。

## 2. 为什么“方向提示”还会改变放行量

动作空间把方向和放行档位绑定在同一个编号里：0—3是北侧的25%、50%、75%、100%，4—7是南侧同样四档，8是等待。因此原版本虽然在方向已经一致时保持档位，换方向时仍可能同时换档位。

AULL0010第15秒的实际改动是：北侧50%（动作1）改为南侧25%（动作4），实际放行上限由每步10人降为5人。新候选保留50%，即改为南侧50%（动作5）。南侧出口容量为9人/步，北侧为3人/步；南侧同时也是预报烟气来源，因此单看“避开预报火源”或“选大出口”都不足以判断最终收益。

从同一个真实状态出发，固定后续使用无建议PPO，分别测试方向与档位的四种组合。以下为即时模式、权重605的旧人口状态；FED差为候选减基线，负数表示更低暴露。

|---|---:|---:|---:|---:|---:|
|Rule / 0070|-0.010557|+0.017669|-0.009195|-0.002083|+4.896|
|Rule / 0071|-0.010281|+0.011432|+0.002679|+0.003830|+0.312|

四行的方向项都有益，容量项都增加暴露，但交互项并不固定为正。按初始240人归一化的房间FED增加分别为0.020406、0.000190、0.010573、0.010573。这为“降低放行档位增加房间停留与暴露”提供了直接模拟证据，但不能推成所有场景中放行越大越好。

表中房间停留是房间人数乘时间、再除以初始240人，表示每位初始人口平均的房间人秒，包含失能之前的停留；它不是全员成功疏散时间。概率行为的数值是四个配对未来的均值，并不是四批独立建筑。

## 3. 为什么修正容量后仍有损失

AULL0024中，北侧出口容量为10人/步，南侧为3人/步；建议避开北侧预报烟气，转向南侧。实际动作1→5始终是50%放行，所以保留档位修正完全不改变这个病例。

在Rule、权重602、人口1477100150的真实轨迹上：

- 第0秒只强制一次南侧建议、随后统一使用无建议PPO，终点FED只增加0.000723，失能人数不变。
- 如果随后恢复建议控制，建议在第15秒再次改变动作；第0秒两种强制动作之间的终点FED差变为+0.018780，失能率差为+2.0833个百分点，即该240人模拟中增加5人失能。
- 在第15秒的真实状态直接比较动作1与5，南侧建议使FED增加0.018057、失能增加5人，房间平均停留增加6.042秒、房间FED增加0.020921。

另一批Rule人口的第15秒状态同样增加5人失能；概率行为的两批旧人口在四未来均值下增加0.5208个百分点失能。损失与指向低容量出口后的等待增加一致。这里不能把问题解释为“降低了放行档位”，也不能因为第0秒单次效果微小，就假设后续再次采纳也无害。

这些改动发生在第0秒或第15秒，未超过冻结的15秒有效期。时间戳校验工作正常；建议仍在有效期内，也不代表它在当前状态值得再次覆盖PPO。

AULL0013和AULL0019还保留人口、行为及后续控制引起的收益反转。例如AULL0013第0秒，两个Rule人口的单次FED差分别为+0.040209与-0.001109。现有公开聚合观测没有完整记录个体分布；这些结果不能成为在线使用隐藏人口或终点答案的理由。

## 4. 新人口完整回合的效果到底多大

下表每行是100个配对比较，来自五个情景、两种行为、每情景两批新人口、五套既有权重。两种时序复用同一批人口，不能合并当成200个独立样本。失能差使用“百分点”，不是相对百分比。

|建议时序|候选减对照|平均FED差|平均失能率差（百分点）|有益 / 有害 / 微小或不变|
|---|---|---:|---:|---|
|即时|保留档位减原提示|-0.000763|-0.0833|4 / 0 / 96|
|实测延迟|保留档位减原提示|-0.000763|-0.0833|4 / 0 / 96|
|即时|保留档位减无建议PPO|+0.001371|+0.0208|5 / 9 / 86|
|实测延迟|保留档位减无建议PPO|+0.000070|-0.0625|6 / 3 / 91|

分类沿用冻结规则：失能差超过±0.001优先，再看FED差超过±0.001。它只是研究描述规则，微小不等于现实安全。

保留档位相对原提示的四个有益配对，全部属于AULL0010、权重605，两种行为各两批人口。每个配对少5人失能，所以在100个配对上平均每回合少0.2人失能。其他96个配对的轨迹没有因这一修正发生变化。这是一个集中的机制修复，不能说五套权重都得到提升。

相对无建议PPO，即时模式平均每回合多0.05人失能；实测延迟模式平均每回合少0.15人失能。这些小均差仍由少数病例决定。AULL0010的新概率人口1487100070虽然比原提示少5人失能，但与无建议PPO相比，失能人数不变且FED增加0.003050，说明“修正比旧版本好”与“比基线好”是两件需要分别检验的事。

按行为拆开，保留档位相对无建议PPO：

|时序|行为|FED差|失能率差（百分点）|
|---|---|---:|---:|
|即时|Rule|+0.002094|0.0000|
|即时|CalibratedLogit|+0.000648|+0.0417|
|实测延迟|Rule|+0.000462|-0.0833|

延迟模式并不是即时模式加一个固定损失：建议到达之前，PPO已经执行了动作，之后是否再次覆盖也不同。AULL0019和AULL0024的新人口延迟模式里，保留档位版本没有产生相对无建议动作的实际改动；零差不等于LLM主动解决了这些冲突。当前不能把延迟组较好的均值推成“延迟越大越安全”。

## 5. 取消指示牌保持时间能否解决问题

我们只在旧人口上取消保持时间，作为机制诊断。正确比较是：

> （候选减无建议）保持0步 − （候选减无建议）保持2步。

原提示版本的FED增量分别减少0.000251（即时）和0.000425（延迟），但平均失能增量没有改善。保留档位版本的FED增量减少0.000363和0.000537，失能增量反而各增加0.0208个百分点。

因此，去掉保持可能改变暴露，但没有给出统一的失能改善。本轮不采用保持0步，也不事后搜索新的保持时长或有效期。

## 6. 本轮决策与下一步的具体方向

保留候选、记录证据，正式方案不自动替换。继续暂停扩大PPO训练，48个保留最终情景封存，不新增LLM请求，不调整Ollama。

下一步应集中检验“当前再次覆盖PPO是否值得”，尤其是重复转向；不能只检查建议是否仍有效、方向是否可走或是否避开预报火源。容量修复作为独立候选保留，便于区分容量问题与剩余方向时机问题。

下一轮开发验证应遵守以下设计：

1. 在线门控只使用当前公开观测、历史公开观测、已有建议时间戳和同状态基线动作。若以反事实收益训练门控，终点答案只能做离线监督，不能成为在线特征。
2. 首次建议和再次建议分别统计，分别比较“保持PPO”“只改方向并保留档位”“允许原提示联动”。一次改动后统一PPO的收益，与恢复建议后的完整收益同时保留，不能相加冒充全程效果。
3. 对相似公开观测下的收益反转先检验可识别性。若现有特征不能区分，就明确拒绝做高置信度覆盖判断，再评估合法的历史队列变化等额外观测；不使用场景编号、隐藏个体属性或未来烟气真值。
4. 根据开发材料制定候选后，再冻结未用于制定该候选的新开发人口或情景作确认。此次新人口结果已用于解释，不能继续作为下一候选的独立确认集。
5. 评价以失能、FED、拥堵及真正全员疏散时间为准，按行为、情景、权重和时序拆分，并与同信息同约束的基线比较。门控拒绝有害建议时，也要统计它误拒绝了多少有益建议。

这仍是同一五区域模拟器中的开发研究。目前有可复现的错误机制证据，还没有独立建筑、实测火场或LLM普遍优于规则与PPO的证据。
